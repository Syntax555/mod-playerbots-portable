# Repository guidance

- Keep README and release notes concise, professional and focused on the current product: installation, supported behavior and relevant limits.
- Describe what users can do. Avoid conversation history, "we replaced", "now fixed", dated audit addenda and prior release narratives.
- Put detailed settings, source revisions and adaptations in the linked guides and dependency manifest. Preserve accuracy, actionable upgrade steps and material gameplay limitations.
- Use one rolling `latest` tag and **Latest** release with stable asset names. Publish only verified server and matching client packages; preserve current downloads until replacement assets are verified.
- The launcher and build tools are MIT-licensed. Upstream files retain their own terms; do not apply MIT to the complete distribution or invent a license for a dependency.
- Preserve user configuration, characters and databases when changing installation or packaging.
